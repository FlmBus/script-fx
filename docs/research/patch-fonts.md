# Patch fonts: image-based and SVG fonts

_2026-11-19. Question (Flemming): support image-based fonts; can a font be an SVG file (good for
fonts generated by an LLM); is there a common way? Status: **built for the library card title
(2026-11-19)**; ControlPanel text in these fonts is next (see "Next")._

## Today

- Fonts are theme tokens: `theme.fonts = { title = Font.new("fonts/x.ttf"), … }` (any names);
  the library card uses `fonts.title` (or `theme.library.font`). TTF/OTF in `<patch>/fonts/` are
  also available to the ControlPanel's SVG text (resvg, per-patch font database).
- Shell isolation (done): every patch font is loaded into iced under a private family name
  (`SFX <hash> <family>`, hash of patch folder + file content, written into a copy of the font's
  `name` table, `crates/plugin/src/shell/brand.rs`). A patch font called "Inter" can't restyle the
  shell, and patches can't use each other's fonts.

## Common formats

| Format | What it is | Status | Fit |
|---|---|---|---|
| **SVG 1.1 fonts** | One SVG document: `<font>` with `<font-face units-per-em ascent descent>`, one `<glyph unicode="A" horiz-adv-x="620" d="…"/>` per character, `<hkern u1="A" u2="V" k="40"/>` for kerning. A glyph may also contain arbitrary SVG shapes instead of `d` (multicolour). | W3C standard (2001), dropped from SVG 2 and from browsers (only Safari kept it). Still read and written by FontForge and Inkscape (SVG font editor). | **Best for LLMs**: one text file, every glyph a path, the layout data explicit. |
| **One SVG per glyph** | A folder `A.svg`, `a.svg`, `uni2192.svg`, … compiled into a font. | The standard icon-font workflow (fantasticon, svgtofont, IcoMoon); Google's nanoemoji compiles SVGs into colour fonts (COLRv1 / OT-SVG). | Good for editing single glyphs; needs a manifest for advances/kerning. |
| **OpenType-SVG / COLR** | Colour glyphs inside an OpenType file. | Supported by browsers and OSes. | Binary container: not writable by hand or by an LLM. |
| **BMFont** (AngelCode) | Text `.fnt` (char id, x/y/width/height in the atlas, offsets, advance, kerning pairs) + PNG atlas. | The common bitmap-font format of game engines; generators: BMFont, Hiero, fontbm. | **Image-based fonts** (raster lettering, pixel fonts, hand-made letters). Same idea as Kontakt's picture fonts and our sprite sheets. |

## Recommendation

1. **Formats:** `fonts/x.ttf|otf` (as now), `fonts/x.svg` (SVG 1.1 font subset: `font-face`,
   `glyph` with `d` or child shapes, `missing-glyph`, `hkern`), `fonts/x.fnt` + PNG (BMFont text
   format) for image fonts. The LLM writes SVG fonts.
2. **Rendering: our own layout, no font compilation.** Display lettering (titles, labels, values)
   needs advances + kerning, not shaping. Text in an SVG/bitmap font becomes glyph paths / image
   regions:
   - ControlPanel: the UI API (e.g. `SVG.text{ font = "fonts/brush.svg", … }`) emits `<path>`/
     `<use>` (or `<image>` regions) into the component's SVG; resvg renders it as before.
   - Shell (library card title): the same layout rendered by resvg into an image.
   - Multicolour glyphs and textured lettering work naturally (a glyph is any SVG).
   Compiling SVG fonts into TTF instead would make them work in every text widget, but loses
   multicolour glyphs and needs a font compiler; not worth it for display text.
3. **Sandbox:** SVG fonts go through the same SVG path as panels (usvg, no scripts, images only
   from the patch folder); BMFont atlases through the same PNG decoder. Limits on glyph count and
   file size.
4. **Typing in a patch font** (text inputs) stays TTF/OTF only.

## Built (2026-11-19)

- `ui_components::glyph_font`: loads SVG fonts (`font-face`, `glyph` with `d` or child shapes,
  `missing-glyph`, `hkern` incl. comma lists) and BMFont text files (single page, kerning), lays
  out one line (advances + kerning), renders with resvg / tiny-skia. SVG glyphs drawn in
  `currentColor` take the requested colour. Sandbox: files inside the patch folder only (atlas
  pages too), ≤ 4 MB, ≤ 2048 glyphs, ≤ 200 characters, glyph rectangles inside the atlas.
- `Font.new` accepts `.svg` and `.fnt` too; the library card shows the patch name rendered in
  its title font (at 2× for HiDPI). Factory: Clean Gain → `fonts/clean-line.svg` (monoline, small caps,
  kerning; generated by `tools/make_clean_gain_svg_font.py`), Junkyard Amp → `fonts/label-tape.fnt`
  + `.png` (label-maker tape; `tools/make_junkyard_bmfont.py`).
- Preview: `cargo run -p ui-components --example glyph_font -- <patch dir> <font> "<text>" out.png [size] [#rrggbb]`.
